# Правила документации lovix-docs

Как делаем страницы в этом репо. Действуют для **новых** страниц; существующие приводим к стандарту при следующей содержательной правке — не переделываем ретроспективно ради переделки.

## 0. Скоуп репо

- Это дока **только про Lovix**. Доки других продуктов (Раздеватор и прочие) живут в своих отдельных проектах — сюда не добавляем.
- Спека — это **бизнес-правила и архитектура**: набор правил, флоу, критерии приёмки. Дизайн, готовый код компонентов и реализация под конкретные стеки в спеку не входят.
- Дизайн и интерактивные прототипы интерфейсов живут в отдельном дизайн-проекте (у Сержа), не в этом репо.

## 1. Три темы оформления

У каждой страницы ровно одна из трёх тем — по её назначению.

### 1.1 Документация и спеки — белая, чистая

Шаблон — `scenarios.html`: светлый фон, системный шрифт, синий акцент `#2f54c9`, контент как markdown внутри `<script type="text/markdown" id="src">` (рендер marked@12). Никаких тёмных секций и декоративных градиентов.

Каркас страницы — трёхколоночный `.shell` (грид `264px / minmax(0,1fr) / 252px`):

- **Слева `.sidenav`** — общее меню сайта: логотип (`emails/img/logo-dark.png`) и группы «Токеномика», «Взаимодействие с юзером», «Рассылки», «Другие доки». Одинаково на всех страницах; своя страница помечается классом `cur`.
- **Центр `<main>`** — контент.
- **Справа `aside.toc`** — оглавление «На этой странице»: строится скриптом по h2/h3, подпункты сворачиваемые, активный пункт подсвечивается при скролле. На ширине ≤1160px скрывается, ≤1000px сайднав становится верхним блоком.

Полноширинные приложения-демо (`admin-demo.html`) — единственное исключение без каркаса: на них ведёт ссылка из спеки и пункт меню.

### 1.2 Демо функционала админки — светлый UI реальной админки, 1 в 1

Референс — окно в `admin-demo.html`. Токены:

| Что | Значение |
|---|---|
| Поверхности | `#ffffff`, фон рабочей области `#f8fafc` |
| Бордеры | `#e2e8f0`, приглушённые `#cbd5e1` |
| Текст | `#0f172a`, вторичный `#64748b` |
| Акцент | `#2563eb` (ссылки, вкладки, pin, чекбоксы) |
| Ошибка/«мало» | `#dc2626`, успех/«вручную» `#16a34a` |
| Тулбар | синий `#2563eb` · зелёный `#16a34a` · фиолетовый `#7c3aed` · индиго `#4f46e5` · violet `#8b5cf6` · teal `#0d9488` · розовый `#db2777` · оранжевый `#ea580c` |

Обязательные элементы окна: хлебные крошки («Админ панель / …»), вкладки с синим underline, кнопки тулбара solid с белым текстом.

### 1.3 Прод-палитра Lovix — только для превью контента

Дизайн-киты и демо интерфейсов в этом репо не делаем (см. «Скоуп репо»). Тёмная прод-палитра используется только там, где спека показывает контент продукта как он есть (например превью письма в `email-template.html`). Токены (сняты с прод-CSS lovix.ai):

| Что | Значение |
|---|---|
| Фоны | страница `#0E0E12`, карточка `#131013`, поверхности `#221A2A` / `#2A1A31` |
| Бордер | `#342A3E` |
| Текст | `#FFFFFF` / `#A3A3B4` / `#80808C` |
| Акцент | градиент `linear-gradient(96deg,#D946EF 0%,#F43F5E 100%)`, ссылки `#F19BF6` |
| Шрифт | Nunito (Google Fonts), код — JetBrains Mono |
| Портреты | реальные с CDN `cdn.test.lovix.ai/ioss(quality=85,resize=N)/prod/templates/…` + фолбэк на градиентный инициал |

## 2. Спека для разработчиков — обязательный состав

Каждая спека содержит:

- **Флоу-схему** — интерактивный канвас (mermaid + pan/zoom, либо кастомный флоу): событие → условие → результат.
- **Критерии приёмки** — отдельный раздел проверяемых пунктов («что можно ткнуть и убедиться»), не пересказ требований.

Рекомендуемые блоки: сводные таблицы с ID, «Принятые решения» (что принято/отклонено — одной строкой, чтобы тред не заменял спеку), декомпозиция задач S/M/L, взаимные ссылки спека ↔ демо.

## 3. Чек-лист структуры — прогонять перед каждым пушем новой страницы

- [ ] Страница встроена в трёхколоночный каркас `.shell`: слева `.sidenav`, справа TOC «На этой странице» (см. 1.1).
- [ ] Пункт меню положен в существующую группу сайднава; новая группа — только по договорённости в чате.
- [ ] Пункт меню добавлен **во все** `.sidenav`: рукописные страницы (включая `index.html` главной), партиалы `_n/_e/_m_head.html` и `_p0_head.html` (там ссылки с префиксом `../`).
- [ ] На новой странице `cur`-подсветка своего пункта.
- [ ] Спека и её демо ссылаются друг на друга.
- [ ] Устаревшая страница убрана из нав (файл остаётся в репо).
- [ ] Мобильная ширина: нет горизонтального скролла, широкое скроллится внутри своего контейнера.

## 4. Технические конвенции

- Страница — самодостаточный html: инлайн CSS/JS; внешнее только с jsdelivr, Google Fonts и CDN Lovix.
- Контентные страницы собираются сборщиком `build.sh` из md-мастеров (`MODULE_*.md`) и партиалов (`_*_head/_foot/_sep/_tail.html`); собранный файл несёт комментарий `СГЕНЕРИРОВАНО … — НЕ ПРАВИТЬ РУКАМИ`. Руками правим только мастера, партиалы и рукописные страницы.
- Перед пушем всегда `git pull --rebase` — в репо параллельно пушат несколько сессий.
- Тексты по-русски, без воды: короткие вводные, таблицы вместо эссе.

## 5. Ченджлог

Каждое содержательное изменение доки — строка в `CHANGELOG.md` **тем же коммитом**: `- страница: что изменилось`. Ченджлог живёт только в репозитории — на Pages не публикуется и в нав не добавляется.
