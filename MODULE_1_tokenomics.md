**Объём токенов VIP — от формулы, округлён до маркетингового значения:**

```
база     = округление вверх( VIP_PRICE ÷ (PREMIUM_TOKEN_PRICE × 0,9) )
         = округление вверх( 1590 ÷ (3,30 × 0,9) ) = 536
VIP_GRANT = 550  — округление базы до маркетингового значения
```

Формула задаёт минимум (скидка на токен не менее 10%), итог округляется вверх до круглого числа. Фактическая скидка при 550 — 12%. При изменении цены любого тарифа база пересчитывается и объём заново округляется.

**Цена токена** = цена тарифа ÷ объём токенов за период. Расчётная величина, основа лестницы.

**Проверка Т4 на текущих ценах:** маржинальная цена токена при переходе Premium → VIP = (1590 − 990) ÷ (550 − 300) = **2,40 ₽**. Пакеты по правилу Т1 дороже 3,30 ₽ за токен, значит апгрейд всегда выгоднее докупки — лестница сходится.

### Правила лестницы

Проверяются при каждом изменении любой цены.

| № | Правило | При нарушении |
|---|---|---|
| Т1 | Цена токена в тарифе ниже цены токена в любом пакете | Подписка теряет смысл как источник токенов, пользователи уходят в разовые покупки |
| Т2 | Цена токена в VIP ниже, чем в Premium | Отличие старшего тарифа отсутствует |
| Т3 | Объём токенов VIP больше объёма Premium | Отличие старшего тарифа отсутствует |
| Т4 | **Маржинальная цена токена при переходе Premium → VIP ниже цены токена в самом выгодном пакете.** Считается: (цена VIP − цена Premium) ÷ (объём VIP − объём Premium) | **VIP не покупают** — выгоднее остаться на Premium и докупать пакеты. Несущее правило лестницы |
| Т5 | Цена токена в пакете для VIP не выше, чем для Premium | Пакет работает доводом против старшего тарифа |
| Т6 | Длинный период даёт либо больший транш, либо скидку на цену — не оба в полном размере | Годовой тариф снижает маржу дважды |
| Т7 | Объём тарифа покрывает типичное потребление, но не потолок — целевая доля `TARGET_COVERAGE_PCT` | При избыточном объёме пакеты не продаются, при недостаточном тариф воспринимается неполноценным |

### Локали, валюты и способы оплаты

Сервис мультигео. RU-версия, EN-версия, дальше — новые локали.

```
Локаль (RU / EN / DE …) ──► меняет только тексты и витринную валюту карточек
                            цены и способы оплаты — те же

Способ оплаты                Валюта         Провайдер
Visa/Master (бурж)    ──►     USD     ──►   Payzmoon
Крипта                ──►     USD     ──►   NOWPayments
РФ-карта              ──►     RUB     ──►   Точка
СБП (не подключён)    ──►     RUB     ──►   Точка

Цена из тарифа: тариф × валюта = одна цена, без пересчёта по курсу
```

| № | Правило |
|---|---|
| Л1 | **Локаль = тексты + витринная валюта карточек.** Витринная валюта задаётся вручную на локаль: RU — ₽, EN — $. Больше локаль не определяет ничего |
| Л2 | **Набор способов оплаты один для всех локалей.** Фильтрации способов по локали нет |
| Л3 | **Валюту платежа определяет способ оплаты**: бурж Visa/Master → USD, крипта → USD, РФ-карта → RUB, СБП → RUB. Для рублёвых способов — всегда рубли, без вариантов |
| Л4 | **Цепочка покупки:** выбрал тариф → выбрал способ → определилась валюта → цена из тарифа. Тариф × валюта = одна цена. **Конвертация валют в платёжном контуре отсутствует** |
| Л5 | У тарифа и пакета — набор цен, по одной на валюту. В админке — одно ценовое поле на валюту |
| Л6 | Витринная валюта и валюта платежа могут расходиться: карточка RU показывает 990 ₽, выбор бурж-карты даёт на чекауте $12.99. Смена цены показывается явно, не подменяется молча |
| Л7 | **Продление — способом первого платежа, в его валюте, по её цене.** Сумма продления не меняется от платежа к платежу. Крипта — без автосписания: продление вручную, по напоминанию до окончания периода |
| Л8 | Зачёт при апгрейде и возвраты — в валюте, которой платил пользователь. Кросс-валютных операций нет |
| Л9 | **Хранение: Провайдер → Способ → [валюты].** Новая платёжка или валюта — добавление в список способа, без переделки. Если один способ появится у двух провайдеров — маршрутизация по приоритету провайдера; поле приоритета закладывается сразу |
| Л10 | Кроме текстов и витринной валюты, локаль не меняет ничего: токены, транши, лимиты, состав тарифов, механика — глобальные |
| Л11 | Все расчёты — цена токена, лестница Т1–Т7, зачёт, возвраты — ведутся внутри каждой валюты отдельно |
| Л12 | Курс валют используется только во внутренней сводной отчётности. На цены и продуктовые расчёты не влияет |

### Апгрейд Premium → VIP: расчёт доплаты

Возврат денег при апгрейде не используется. Неиспользованный остаток Premium **зачитывается** в оплату VIP:

```
доплата = цена VIP − цена Premium × (осталось дней ÷ дней в периоде)
```

Пример: Premium 990 ₽, прошло 18 из 30 дней → зачёт 990 × 12/30 = 396 ₽, доплата = 1590 − 396 = **1194 ₽**.

| № | Правило |
|---|---|
| А1 | VIP включается **немедленно** после доплаты. Новый период — со дня апгрейда, следующее списание через период по полной цене VIP |
| А2 | Зачёт считается от **фактически уплаченной** цены (с учётом скидки периода), не от номинала. У годового Premium день стоит 26 ₽, а не 33 ₽ |
| А3 | Если зачёт превышает цену VIP (годовой Premium → месячный VIP), доплата = 0, излишек зачёта конвертируется в дополнительные дни VIP |
| А4 | Расчёт в целых днях, округление — в пользу пользователя |
| А5 | Legacy → VIP — та же формула, зачёт от 990 ₽ |
| А6 | Понижение VIP → Premium — без движения денег, со следующего цикла. Зачёт применяется только к апгрейдам |
| А7 | Пользователю показывается одной строкой: «Осталось N дней Premium — зачтём их. Доплата сегодня: X ₽» |
| А8 | Оплата — **привязанным методом по умолчанию**, одним действием. «Другой способ оплаты» — вторичной ссылкой |
| А9 | Нет привязанного метода — обычная платёжная форма. Успешный метод привязывается |
| А10 | **Неудачное списание при апгрейде не затрагивает действующую подписку.** Окно восстановления не применяется. Показывается причина по `decline_code` и предложение другого способа оплаты |
| А11 | Сумма доплаты не резервируется: зачёт пересчитывается **на момент фактической оплаты** |
| А12 | Метод, которым успешно оплачен апгрейд, становится методом автопродления |

### Доступность операций по тарифам

| № | Правило |
|---|---|
| Т8 | Операция может быть недоступна на тарифе независимо от баланса. **Недоступность по тарифу и нехватка токенов — разные сообщения.** Иначе пользователь купит пакет и обнаружит, что операция всё равно недоступна. Для VIP-операций (видео, звонки) это сообщение — точка апсейла Premium → VIP |
| Т9 | **Все тарифицируемые операции доступны только на платных тарифах.** На Free операции закрыты независимо от баланса: никакие токены — в том числе замороженные купленные — их не открывают. Единственное исключение — разовые пробные операции из пробного набора (раздел 5). Сообщение при попытке — предложение подписки |
| Т12 | **VIP-функции видны всем всегда** — и на Premium, и на Free. На своём месте в интерфейсе (кнопка звонка рядом с сообщениями, видео рядом с фото), а не в отдельном разделе. Для не-VIP помечаются плашкой «VIP». Скрывать нельзя: скрытая функция не продаёт |
| Т13 | Плашка — приглашение, не запрет: акцентная метка «VIP», не серый замок. Клик по функции с плашкой ведёт на предложение апгрейда с расчётом доплаты (А7). Фиксируется, **с какой функции пришёл клик** — это показывает, какие VIP-функции реально продают апгрейд |
| Т14 | Внутри активного диалога VIP-подсказки не показываются. Продажа — на входах в функции, не внутри опыта общения |

## 3. Прайс-лист операций

| № | Правило |
|---|---|
| Ц1 | Все тарифицируемые операции ведутся **единым прайс-листом**. Стоимость каждой хранится в настройках, не в коде |
| Ц2 | **Добавление операции — настроечное действие**, не доработка |
| Ц3 | У операции задаются: наименование для пользователя, стоимость в токенах, доступность по тарифам |
| Ц4 | Стоимость — целое число токенов. Дробных токенов нет |
| Ц5 | Стоимость может различаться по тарифам; по умолчанию едина |
| Ц6 | Изменение стоимости задаётся с датой вступления в силу, задним числом не применяется |
| Ц7 | Номинал: стоимость самой частой операции — **десятки токенов**. Это даёт запас на операции дешевле и дороже без пересчёта балансов |

| Операция | Стоимость в токенах | Себестоимость | Единица |
|---|---|---|---|
| Генерация фото | `PHOTO_COST` | `PHOTO_COGS` | за фото |
| Аудио сообщение | `AUDIO_MSG_COST` | `AUDIO_MSG_COGS` | за сообщение |
| Генерация видео | `VIDEO_COST` | `VIDEO_COGS` | за видео |
| Аудио звонок | `CALL_COST` | `CALL_COGS` | `[?]` — за звонок или за минуту |
| Текстовое сообщение | 0 | `MESSAGE_COGS` | за обмен сообщениями |

У каждой операции две переменные:

- **Стоимость в токенах** (`*_COST`) — видна пользователю, задаёт, на сколько действий хватает транша.
- **Себестоимость** (`*_COGS`) — **пользователю не показывается никогда.** Используется только в расчёте маржи тарифа и маржи каждой операции (раздел 14).

Обе — рабочие переменные управления маржой: корректируются без изменения цен тарифов и объёмов токенов. Групповые чаты и нейромодель Lovix 2.0 токенов не расходуют — это функции тарифа, а не операции прайс-листа.

### Сообщения

| № | Правило |
|---|---|
| Ц8 | Обмен текстовыми сообщениями токенов не расходует. Ограничения: Free — 5/мес; Premium — 500/день, лимит виден пользователю; VIP — показывается «безлимит», внутри скрытый предел 1200/сутки |
| Ц9 | Сообщения и токены не пересекаются: пакет токенов не увеличивает лимит сообщений. Пакет токенов в точках исчерпания лимитов не предлагается никогда |
| Ц10 | **Поведение при достижении дневного лимита** — сообщение с просьбой подождать до завтра, лимит обнуляется в новые сутки. Free (5/мес) — предложение подписки. Premium (500/день) — предложение VIP либо подождать до завтра. VIP (скрытый предел) — только просьба подождать, без апсейла |

## 4. Источники токенов

| Источник | Откуда | При смене месячного цикла | При падении на Free |
|---|---|---|---|
| **Тарифные** | Ежемесячный транш подписки | **сгорают** | **сгорают** |
| **Купленные** | Пакеты | переносятся, **не сгорают никогда** | **замораживаются** бессрочно |
| **Бонусные** | Промо, компенсации | сгорают, если правилом акции не задано иное | сгорают |

**Решение зафиксировано: перенос неизрасходованных тарифных токенов между месячными циклами не применяется.** Остаток транша сгорает в конце цикла (Н2), купленные пакеты бессрочны (П4). Альтернатива — накопление с потолком — рассмотрена и отклонена.

| № | Правило |
|---|---|
| И1 | **Порядок расходования: тарифные → бонусные → купленные.** Внутри источника — те, что сгорают раньше. При обратном порядке пользователь тратит несгораемые токены, а сгораемые пропадают неиспользованными |
| И2 | Одна операция может быть оплачена из нескольких источников, если в первом не хватает |
| И3 | Пользователь источник не выбирает. Наружу выходит только строка о замороженных токенах |

## 5. Free-тариф: постоянная часть и пробный набор

**Постоянная часть Free — 5 сообщений в месяц. Это единственное, что начисляется регулярно.** Квота обнуляется и выдаётся заново каждый месяц. Больше на Free не начисляется ничего.

**Пробный набор** — настраиваемый список разовых пробных операций поверх постоянной части. Пример: 1 генерация фото + 1 аудио сообщение. Логика динамична: завтра набор можно включить, послезавтра убрать.

| № | Правило |
|---|---|
| С1 | Состав набора задаётся в настройках: список пар «операция × количество». Набор может быть пустым — **сейчас он пуст**, Free даёт только 5 сообщений в месяц |
| С2 | Набор выдаётся **разово**: один раз при регистрации и один раз при даунгрейде с платного тарифа. Не возобновляется, не накапливается, ежемесячно не сбрасывается |
| С3 | Пробные операции — **не токены**, а счётчики конкретных операций («осталась 1 пробная генерация фото»). Токеновый баланс на Free по-прежнему потратить нельзя (правило Т9) |
| С4 | Изменение состава действует **только на будущие выдачи**. Уже выданные наборы не пересматриваются и не изымаются |
| С5 | Состав может назначаться по варианту эксперимента; вариант фиксируется в момент выдачи |
| С6 | Каждая выдача фиксируется: состав, причина (регистрация / даунгрейд), действовавшая настройка |
| С7 | **Исчерпание пробной операции — точка предложения подписки.** Продающая функция набора — дать попробовать платную возможность и упереться в её отсутствие |

Повторная выдача при каждом даунгрейде злоупотреблений не создаёт: чтобы получить набор снова, нужно оплатить и завершить платный период.

## 6. Начисление тарифных токенов

| № | Правило |
|---|---|
| Н1 | Начисление — **равными ежемесячными траншами**: 1 транш при периоде месяц, 3 при трёх месяцах, 12 при годе. Единовременная выдача всего объёма запрещена |
| Н2 | Остаток транша сгорает в конце месячного цикла. Цикл привязан к траншу, не к оплаченному периоду |
| Н3 | Транш начисляется в дату-годовщину оплаты; если такого числа в месяце нет — в последний день месяца |
| Н4 | Первый транш — немедленно при успешной оплате |
| Н5 | За `EXPIRY_WARNING_DAYS` до сгорания остатка отправляется предупреждение. Оно касается только тарифных токенов; купленные не упоминаются — они не сгорают |
| Н6 | Выгода длинного периода — в размере транша или в цене, не в единовременной выдаче |
| Н7 | Формулировка для пользователя — «N токенов каждый месяц». Помесячная выдача указана в условиях тарифа |

### Смена тарифа

| Событие | Токены |
|---|---|
| Переход на старший тариф | Разница траншей доначисляется немедленно, пропорционально остатку цикла |
| Переход на младший тариф | Со следующего цикла. Текущий транш не пересчитывается и не изымается |
| Продление того же тарифа | Остаток тарифных сгорает, начисляется новый транш. Купленные не затрагиваются |
| Возобновление после закрытия | Первый транш нового периода, купленные размораживаются |

| № | Правило |
|---|---|
| Н8 | **Изъятие уже начисленных токенов запрещено** — пользователь уже видел этот баланс |
| Н9 | Операции, недоступные на новом младшем тарифе, отключаются со следующего цикла, одновременно со сменой объёма |

## 7. Расходование

| № | Правило |
|---|---|
| Р1 | Списание — **при постановке операции в работу**, не после завершения. Иначе пользователь запустит больше, чем может оплатить |
| Р2 | Проверка баланса и списание — одно неделимое действие |
| Р3 | При нехватке операция не запускается, списания нет, факт нехватки фиксируется |
| Р4 | Перед списанием проверяется доступность операции на тарифе. Недоступная не запускается даже при достаточном балансе |
| Р5 | Одновременные запросы принимаются по порядку поступления, пока хватает баланса |

### Возвраты токенов

| Случай | Токены |
|---|---|
| Ошибка выполнения, таймаут | возвращаются полностью |
| Блокировка модерацией | возвращаются полностью |
| Отмена до начала обработки | возвращаются полностью |
| Отмена после начала обработки | не возвращаются; условие показывается до запуска |

| № | Правило |
|---|---|
| Р6 | Возврат — **в тот же источник**, из которого списано. Возврат тарифных в купленные создал бы несгораемые токены из ничего |
| Р7 | Возврат автоматический, до уведомления пользователя. Обращение в поддержку не требуется |
| Р8 | Если исходный транш уже сгорел, возврат идёт в бонусный источник со сроком до конца текущего цикла |

## 10. Переход с текущего тарифа

Контекст: до запуска новой сетки действует один тариф — 990 ₽/мес, включающий весь функционал продукта. Новая сетка вводит Premium (990 ₽, урезанный состав) и VIP (1590 ₽). У действующих подписчиков функционал шире нового Premium при той же цене.

**Принцип: у действующего подписчика ничего не отнимается.** Принудительный перевод на Premium — это отъём оплаченной функциональности: прямой источник оттока, жалоб и возвратов средств.

| № | Правило |
|---|---|
| М1 | Действующие подписчики на дату запуска переводятся на закрытый тариф **Legacy**: прежняя цена, прежний состав функций, прежний объём токенов. Для пользователя не меняется ничего |
| М2 | Legacy недоступен для новых подключений. Существует только для подписчиков, активных на дату запуска |
| М3 | **Состав Legacy заморожен на дату запуска новой сетки.** Всё, что появляется в продукте после этой даты — Lovix 2.0, генерация видео, аудио звонки, групповые чаты и любые будущие функции — попадает только в новые тарифы. У Legacy ничего не отнимается, но ничего и не добавляется |
| М4 | Лимиты сообщений новой сетки к Legacy не применяются: сохраняется поведение текущего тарифа. Скрытый технический предел (1200/сутки) действует — он защита, а не условие тарифа |
| М5 | Legacy сохраняется, пока подписка продлевается **без разрыва**. Разрыв — неоплата после дня 4, отмена с истечением периода, возврат средств — означает **безвозвратную утрату Legacy**: вернуться можно только на Premium или VIP |
| М6 | Переход Legacy → VIP добровольный, в любой момент. Обратный переход на Legacy невозможен ни при каких условиях |
| М7 | Переход Legacy → Premium (осознанное понижение) разрешён, вступает в силу со следующего цикла. Возврат на Legacy невозможен |
| М8 | Токеновые балансы при миграции не пересчитываются и не изымаются |
| М9 | Подписчики уведомляются **до даты запуска** с явной формулировкой: «для вас ничего не меняется — цена и возможности сохраняются». Молчаливая миграция порождает панику и волну обращений |

**Как Legacy вымывается.** Тариф сокращается естественно, без принуждения: разрывы подписки переводят на новую сетку (М5), а замороженный состав (М3) делает VIP всё привлекательнее с каждой новой функцией. Продавать апгрейд базе Legacy надо новыми функциями, а не угрозой отключения.

**Правило М5 — главный охранник экономики перехода.** Без него Legacy существовал бы вечно и делал VIP непродаваемым для всей старой базы.
