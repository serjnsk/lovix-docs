# События

Единая таблица событий продукта — контракт между тремя системами: разработка реализует запись, [метрики](metrics.html) читают для расчёта, сценарии взаимодействия подписываются как на триггеры.

Собрана из двух источников: колонки «События-источники» системы метрик и сценарии взаимодействия с пользователями.

## Общие правила

| № | Правило |
|---|---|
| С1 | Событие записывается **сервером в момент факта**. Клиентские события допустимы только для интерфейсных действий и помечены 🖱 |
| С2 | Каждое событие несёт базовый набор: пользователь, **тариф на момент события**, локаль, время. В таблицах ниже эти поля не повторяются |
| С3 | Повторная доставка события **не создаёт дубль** |
| С4 | События, помеченные ⏱ — **производные**: их создаёт планировщик или логика по правилу, а не действие пользователя |
| С5 | Деньги, токены, квоты, подписки — только серверные события. Потерянное клиентское событие — потерянная строка аналитики; потерянное серверное — расхождение денег |
| С6 | Имена событий из этого документа — канонические. Переименование ломает метрики и триггеры одновременно |

Колонка «Метрики» — группы из [системы метрик](metrics.html). Колонка «Сценарии» — сценарий взаимодействия, формализованный в документе [«Сценарии»](scenarios.html).
