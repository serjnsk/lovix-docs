# Саппорт — инструкция QA + Support

Как разбирать входящие обращения по продуктам **Lovix · Milki · Botfans · Examka · Sdal**: что отвечаем сами, что эскалируем и куда. Порядок всегда один: определи тип обращения — дальше действуй по таблице. Типовые ответы — шаблонами из HappyDesk, отсебятину не пишем.

## Каналы

Все обращения сведены в **HappyDesk** — разбираем и отвечаем только там, мимо него в почту и ботов напрямую не отвечаем.

| Продукт | Откуда приходит | Где разбираем |
|---|---|---|
| Lovix, Botfans, Milki | Почта | HappyDesk |
| Examka, Sdal | Telegram-боты | HappyDesk |

## Правила

### П1. Чарджбеки — Lovix, Milki, Botfans

На банковские сообщения о чарджбеках (уведомления банка или платёжки, запросы по спорным операциям) **не отвечаем**: не оспариваем, в переписку не вступаем. Обращение закрываем без ответа.

### П2. Чарджбеки — Examka, Sdal

Отвечаем строго по канону из треда: [тред с ответом по чарджбекам](https://keks.pro/directlinemedia/pl/8x3xftoog7b7xdehwiss6xxwrh). Свои формулировки не придумываем — только согласованный текст оттуда.

### П3. Технические ошибки

Пользователь пишет об ошибке, сбое, «не работает»:

1. Собрать минимум: продукт, аккаунт пользователя, что делал, текст или скрин ошибки, время.
2. Проверить воспроизведение самому; не воспроизводится — запросить у пользователя точные шаги.
3. Завести таску-багу: шаги → ожидание → факт, приложить скрины.
4. Подсветить багу в канале **AI Support** и тегнуть **Даниила Печерского**.

Пользователю — шаблон «Передали разработчикам». Сроки не обещаем.

### П4. Запросы функционала

«Сделайте», «добавьте», «хочу фичу»:

- Похожие просьбы **агрегируем в одну таску** со счётчиком обращений — не заводим таску на каждое сообщение. Повторное обращение по той же теме → +1 к счётчику существующей таски.
- Новая тема → завести таску и написать пост в **общий канал**: что просят, сколько обращений, ссылка на таску.

Пользователю — шаблон «Идею записали».

### П5. Отмена подписки и возвраты

- Просят **отменить подписку** → шаблон продукта «где и как отменить» со скринами (шаблоны — в HappyDesk).
- Требуют **возврат денег** → возврат не делаем: вежливый отказ + тот же шаблон отмены, чтобы остановить дальнейшие списания.
- Шаблона под продукт нет → завести (текст + скрины пути отмены), после этого ответить. Новый шаблон складываем к остальным — второй раз не собирать.

### П6. Агрессивные пользователи

Мат, угрозы, капс — не зеркалим и не спорим:

- Отвечаем спокойно, признаём неудобство, вопрос разбираем по существу — тип определяем по этой же таблице.
- Можно начислить **200–300 койнов** как извинение — **только с аппрува Владислава Рейзлера**. Повторно за тот же инцидент не начисляем.

### П7. Сотрудничество

Реклама, партнёрки, блогеры, «есть предложение» — сами не отвечаем:

- Переслать в **общий канал** и тегнуть **Владислава Рейзлера**.
- Пользователю — шаблон «Передали, свяжутся».

## Шаблоны ответов

Все шаблоны ответов живут в **HappyDesk** — заводятся, правятся и актуализируются только там; тексты на этой странице не дублируем. Правила:

- Отвечаем шаблоном, не отсебятиной; тон спокойный, без канцелярита и без обещаний по срокам.
- **Отвечаем на языке обращения**: русским — RU-версия шаблона, всем остальным — EN.
- Минимальный набор в HappyDesk: отмена подписки (по каждому продукту, со скринами пути), отказ в возврате, извинение + койны, «передали разработчикам», «идею записали», сотрудничество.
- Нужного шаблона нет → завести в HappyDesk (текст + скрины), после этого ответить.

## Чек-лист перед ответом

- Тип обращения определён по таблице; если подходит несколько — приоритет: чарджбек → баг → возврат → остальное.
- Чарджбек по Lovix / Milki / Botfans → ответа быть **не должно**.
- Ответ собран из шаблона HappyDesk, без обещаний по срокам и отсебятины.
- Таска заведена и подсвечена: баг → AI Support + Даниил; фича → пост в общий канал.
- Койны — только после аппрува; повторно за тот же инцидент не начисляем.
